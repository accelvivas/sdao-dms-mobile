SDAO DMS MOBILE API CONTRACT
============================

Purpose
-------
API contract required by the SDAO DMS React Native / Expo mobile app.
The mobile app is approver-only and reviews Activity Proposals.

BASE URL
--------
Configure the mobile app with:

https://your-domain.com/api

All authenticated requests require:

Authorization: Bearer {token}
Accept: application/json
Content-Type: application/json


1. AUTHENTICATION
-----------------

POST /mobile/login

Request:
{
  "email": "demo.adviser@nu-lipa.edu.ph",
  "password": "Password123!",
  "device_name": "SDAO DMS Mobile"
}

Response:
{
  "token": "sanctum-token-here"
}

GET /mobile/user

Response:
{
  "id": 1,
  "email": "demo.adviser@nu-lipa.edu.ph",
  "name": "Demo Adviser",
  "roles": ["approver", "adviser"],
  "mobile_access": true,
  "capabilities": {
    "can_access_mobile_review": true
  }
}

Accounts without mobile access should receive HTTP 403.

POST /mobile/logout

Expected response:
204 No Content

4. APPROVE
----------

POST /documents/{documentId}/approve

Request body:
{}

Return the updated full Activity Proposal document.


5. REQUEST REVISION
-------------------

POST /documents/{documentId}/request-revision

Request:
{
  "remarks": "Please update the activity schedule and budget details.\n\nSections needing revision: Budget, Schedule & Venue"
}

Return the updated full Activity Proposal document.


6. REJECT
---------

POST /documents/{documentId}/reject

Request:
{
  "remarks": "The proposal does not meet the current requirements."
}

Return the updated full Activity Proposal document.


7. ENUM VALUES
--------------

Status values:
pending
in_review
approved
revision_requested
rejected

Workflow stage values:
submitted
adviser_review
program_chair_review
principal_review
completed
rejected

Conditional SHS Principal workflow:

The SHS Principal approval stage must be included only when the submitting RSO
President belongs to Senior High School (SHS).

If the RSO President is an SHS student:

submitted -> adviser_review -> program_chair_review -> principal_review -> completed

If the RSO President is not an SHS student:

submitted -> adviser_review -> program_chair_review -> completed

Laravel must determine this condition from the submitting president's actual
academic level or student classification. The mobile app must rely on the API's
current_stage, total_steps, permissions, and history values and must not infer
the workflow from role names.


8. ERROR RESPONSES
------------------

Validation error: HTTP 422
{
  "message": "The given data was invalid.",
  "errors": {
    "remarks": ["The remarks field is required."]
  }
}

Unauthenticated: HTTP 401
{
  "message": "Unauthenticated."
}

Forbidden: HTTP 403
{
  "message": "You are not allowed to perform this action."
}

Not found: HTTP 404
{
  "message": "Activity Proposal not found."
}


9. ATTACHMENTS
--------------

The current mobile app displays attachment metadata only.
It does not currently call an attachment download or viewing endpoint.

A future endpoint could be:

GET /documents/{documentId}/attachments/{attachmentId}/download

This endpoint is not currently required by the mobile app.
